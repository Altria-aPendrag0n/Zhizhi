# 图片转笔记功能：方案调研与选型总结

> 项目背景：为开源软件新增"图片转笔记"能力，用户上传照片，系统识别照片中的文字与格式信息，并输出为 Markdown（可能包含表格）。本文档汇总了从方案选型、本地部署、API 成本到开源商业模式的全链路调研结论，供技术选型与后续落地参考。

---

## 一、背景与需求

目标功能是把一张图片（以手机拍照、截图为主，可能存在表格）转换成一份结构化 Markdown 笔记。需求拆解后包含三个层次：

| 层次 | 内容 | 说明 |
|---|---|---|
| 识别 | 图片中的文字信息 | 属于 OCR 能力 |
| 理解 | 内容结构、语义关系 | 需要大模型或解析引擎 |
| 整理 | 输出分层级、带表格的 Markdown | 最终交付形态 |

核心约束有三点：最终产出是 Markdown（而非纯文本）；图片可能包含表格，需要还原表格结构；项目定位是开源软件，面向外部用户使用。

## 二、核心判断：为什么纯 OCR 不够

"图片转笔记"不等于"图片识别文字"。OCR 只解决识别这一层，输出的是文本，不是笔记。它不会做摘要、不会分层级、不会把表格还原成 Markdown。如果选纯 OCR，后面还必须再接一个 LLM 来整理，等于走两步。

多模态大模型（如 Qwen-VL）可以一步到位：直接看图，同时完成识别、理解与整理，输出可直接落库的 Markdown 笔记。因此 **纯 OCR 只能作为辅助手段，不适合作为"图片转笔记"的主力方案**。

## 三、方案全景与对比

按技术路线，候选方案可归为三类：

| 类别 | 代表方案 | 表格还原 | 成本 | 特点 |
|---|---|---|---|---|
| 多模态大模型 API | 百炼 Qwen-VL、智谱 GLM-4V | 中上（靠提示词引导） | 低至免费 | 一步到位、接入简单、OpenAI 兼容 |
| 文档解析工具（开源） | MinerU、DeepSeek-OCR | 强（表格/公式/多栏） | 自部署免费 | 专为"文档转 Markdown"设计，输出标准 Markdown |
| 文档解析服务（云 API） | 阿里云 DocMind、TextIn xParse、MinerU 云 API | 强 | 按页计费 | 稳定 SLA、表格识别专项优化 |

关键区分点有两个：**能否直接产出 Markdown 笔记**（多模态模型与文档解析工具可以，OCR 都不行），以及**表格还原精度**（文档解析类工具最强，多模态模型靠提示词引导）。

## 四、本地部署：算力与耗时

本地部署的结论是：**能做，但"出 Markdown 表格"有明确的硬件门槛**。

| 方案 | 显存要求 | 内存 | 单图耗时（GPU） | 输出 |
|---|---|---|---|---|
| MinerU（推荐） | 6~8GB | 16GB 起，推荐 32GB | RTX 4090 约 3.2s/页，3090 约 4.1s/页 | Markdown 表格 |
| DeepSeek-OCR | 12~16GB（推荐 24GB） | 32GB | RTX 4090 约 0.8~2s/页 | Markdown 表格 |
| Qwen-VL-7B | 16GB（BF16）或 6~8GB（量化） | 16GB+ | RTX 4090 约 1.3s/图 | Markdown 表格 |
| PaddleOCR | 2~6GB | 8GB+ | GPU 0.03~0.1s/图，CPU 1~3s/图 | 纯文本，无表格 |

几个关键判断：

- **不是必须上 GPU。** MinerU 支持纯 CPU 运行，能出 Markdown 表格，只是慢；DeepSeek-OCR 和 Qwen-VL 基本需要 GPU。
- **显存是硬门槛。** 能出 Markdown 表格的三个方案里，MinerU 门槛最低（6~8GB），意味着 RTX 3060 12GB 或 RTX 4060 8GB 就能跑；DeepSeek-OCR 和 Qwen-VL 需要 12~16GB。
- **耗时量级。** 单张 1~4 秒（GPU），属于可接受但不实时。批量处理按 3 秒/张算，100 张约 5 分钟；在线等待场景需要 vLLM 加速或并发。
- **性价比结论。** 若面向个人或小团队自用，MinerU + 8GB 显卡可行；但若做进软件给用户用，本地部署的运维与算力成本不低，转向 API 更务实。

## 五、调用 API：成本测算

API 路线的单张成本很低，部分方案在免费额度内可以做到零成本。

| 方案 | 每张成本 | 免费额度 | 说明 |
|---|---|---|---|
| 智谱 GLM-4V-Flash | 0 元 | 完全免费，新用户送 2000 万 token | 免费多模态模型，直接出 Markdown；限 1 并发 |
| 百炼 Qwen-VL-Plus | 约 0.004 元 | 新人 100 万 token（90 天） | 输入 0.0015 元/千 token，一张 720P 图约 1300 token |
| 百度 OCR + LLM | 约 0.006 元 | OCR 每月 5 万次免费 | 两步走：OCR 出文本 + LLM 转表格 |
| MinerU 云 API | 约 0.01~0.02 元/页 | 每日 1000 页免费 | 专为文档转 Markdown 设计 |
| TextIn xParse | 0.015 元/页（批量 0.008 元/页） | 每日 1000 页免费 | 表格/合并单元格还原强 |
| 阿里云 DocMind | 约 0.1 元/页 | 公测期部分免费 | 企业级，最贵 |

月成本参考（按每天 100 张、每月 3000 张估算）：智谱 GLM-4V-Flash 为 0 元；MinerU / TextIn 在每日 1000 页免费额度内为 0 元；百炼 Qwen-VL-Plus 约 12 元；阿里云 DocMind 约 300 元。

**重要提醒：** 上述免费方案（智谱 1 并发、每日 1000 页）只适合开发者自用或验证阶段。一旦做进软件供外部用户使用，量级上来后这些免费额度会立刻不够，必须切换到按量付费或自部署，详见下一节。

## 六、生产化考量：做进软件给用户用

面向外部用户的真实生产场景，选型逻辑与自用完全不同，有三个新增考量维度：

1. **API Key 必须自持。** 供应商 Key 绝不能暴露给用户客户端，必须在服务端统一接管，按用量与自有业务结算。这决定了必须在服务端做一层代理。
2. **数据合规是最大分叉点。** 用户上传的照片可能含证件、票据、个人信息。走第三方 API 意味着图片要出你的网络，需要评估供应商的数据处理协议；如果图片敏感，自部署是唯一数据不出网的选项。
3. **量级决定成本与架构。** 第三方按量计费零启动、最省心；超过一定量级后自部署 GPU 的边际成本更低。

三条路线的取舍：

| 路线 | 代表 | 适合谁 |
|---|---|---|
| 第三方文档解析 API | TextIn / MinerU 云 / DocMind | 最省心、快速上线，接受数据出网 |
| 多模态大模型 API | 百炼 Qwen-VL | 成本最低、最灵活，表格精度略逊 |
| 自部署 MinerU | 云 GPU 实例 | 数据敏感、量级大，或已有 GPU 资源 |

生产架构的关键点：服务端代理层是必须的（统一接管 Key、控制并发、缓存结果、按自有业务计费）；先用试用额度验证表格还原效果再上生产；把"图片转 Markdown"封装成可替换的抽象，为未来平滑切换供应商留好余地。

## 七、开源项目落地：BYOK + 托管双轨

考虑到项目是开源的，最合理的商业模式是 **"开源核心 + BYOK + 托管云服务"** 双轨并行。同一套引擎抽象接口，挂两种来源：

- **BYOK（用户自持 Key）：** 用户在自己的软件里配置自己的供应商 Key，图片走用户自己的账号。你不出算力账单，也不碰用户数据，隐私合规压力大幅下降。
- **托管服务（你代运营）：** 为不想自己配 Key 的用户提供开箱即用、按量付费（建议积分/套餐制）的托管通道，同时形成持续收入。

这种模式的合理性在于三条线互相成就：开源 + BYOK 积累口碑与用户群，托管服务提供变现出口，两者共享同一套 Provider 抽象，代码复用、切换无痛。

落地时的四个关键点：

- **Provider 抽象是地基。** 把"图片转 Markdown"抽成 `ProviderInterface`，BYOK 和托管服务都实现它；接口要能装任意后端，BYOK 路径优先支持 OpenAI 兼容协议（覆盖 GLM-4V / Qwen-VL 等）。
- **BYOK 指服务端代理，不是客户端直连。** 用户把 Key 配置在服务端，由服务端统一限流、缓存、日志，不把 Key 暴露给最终用户浏览器。
- **托管服务解决计费与限额。** 积分/套餐制最省心，用户充值积分、按图片扣减，把"每张几分钱"换算成自有订阅定价。
- **License 决定托管护城河。** 核心引擎若希望防止他人白嫖托管能力，可采用 AGPL / elastic 等协议而非纯 MIT，但这会吓退一部分企业用户，需权衡。

务实启动顺序：先做开源 + BYOK 低成本跑通、验证需求，托管服务作为 V2 加入。用开源用户的真实反馈打磨引擎，确认有人愿意用之后再投入托管与计费，风险最小。

## 八、结论与建议

1. **方案主线：** 以"文档解析 + 多模态大模型"为主，纯 OCR 仅作辅助。个人/小批量自用可用智谱 GLM-4V-Flash（零成本）或 MinerU / TextIn 的免费额度；生产环境用 TextIn / MinerU 云 API（表格还原强、SLA 稳定）作为主力，自部署 MinerU 作为数据合规备选。
2. **本地部署：** 可行但非首选。单张 1~4 秒、显存 6~16GB，适合自用或数据敏感场景；做进软件给用户用，优先考虑 API。
3. **开源模式：** 采用"开源核心 + BYOK + 托管服务"双轨。第一步先把 `ProviderInterface` 抽象层设计好，这是整个架构可持续的关键。
