# 复习时间轴（未来一周）开发方案

> 目标：在复习界面（学习地图 `review` 视图）标题区之下、到期清单之上，新增一条**未来一周复习时间轴**：横向 7 天卡片，展示每天有多少复习、分别是什么。
> 本方案经逐分支确认（2026-09-03），决策已定稿，见「二、设计决策」。
> 纯客户端功能：数据全部来自 `reviewStore.queue`（`ReviewTask.dueAt` 为权威到期时间，classic/FSRS 评级后均会更新），无新增存储与接口。

***

## 一、背景

复习界面目前只展示「今天到期」的清单（`ReviewDueList`），用户看不到未来几天的复习节奏。时间轴把未来 7 天的复习量与内容前置展露，帮助用户预判负载、安排学习。

## 二、设计决策（已定稿）

| # | 决策点 | 结论 | 理由 |
|---|--------|------|------|
| 1 | 形态 | **横向 7 天卡片条**：每张日卡显示日期/星期/数量徽章，卡内列当天到期笔记标题 | 紧凑不挤压到期清单，一览一周节奏 |
| 2 | 数据口径 | 只统计**未毕业**任务（与 `buildDueList` 语义一致）；`dueAt` 早于今天 0:00 的**逾期任务归入今天卡**并标注「含 N 项逾期」；窗口 = 今天 0:00 起 7 个自然日（本地时区，含今天）；已毕业任务不入轴 | 毕业任务本就不进复习流程；逾期本质是「今天该做」 |
| 3 | 条目交互 | 点击条目 = **打开笔记详情页**（与到期清单的 open 语义一致，回看原文）；不做「点击直接复习」 | 提前复习会立即重排 dueAt，时间轴预测自我失效；打开笔记不干扰调度 |
| 4 | 密度 | 每卡默认展示 **4 条**，更多时显示「+N」点击展开/收起（展开的卡允许变高，同行顶部对齐）；今天卡高亮边框 + 「今天」标 | 控制整行高度，避免喧宾夺主 |
| 5 | 空态 | **7 张卡始终渲染**，无任务的天显示「无」 | 用户明确选择：「未来一周很空闲」本身是信息 |

## 三、实现设计

### 3.1 聚合纯函数（`utils/review-scheduler.ts` 内新增，可单测）

```ts
export interface ReviewTimelineDay {
  /** 本地时区日期键 YYYY-MM-DD（同时用于分组与「今天」判定） */
  dateKey: string
  /** 该日 0:00 的 Date（展示用） */
  date: Date
  isToday: boolean
  /** 归入该卡的逾期任务数（仅今天可能 > 0） */
  overdueCount: number
  /** 该日到期任务（逾期归今天的已在内），保持 dueAt 升序 */
  tasks: ReviewTask[]
}

/** 未来 7 天复习时间轴：未毕业任务按本地自然日分组，逾期归今天，窗口 = 今天 0:00 起 7 天 */
export function buildReviewTimeline(
  tasks: ReviewTask[],
  now: Date = new Date(),
  days = 7,
): ReviewTimelineDay[]
```

要点：

- 以本地时区的自然日切分（`dateKey` 由年/月/日本地值生成，不用 toISOString 的 UTC 日期）；
- 逾期判定：`dueAt < 今天0:00`；今天卡的任务 = 逾期任务 ∪ dueAt ∈ [今天0:00, 明天0:00) 的任务，逾期排前；
- 已毕业（`graduated: true`）过滤，与 `buildDueList` 一致。

### 3.2 组件（`components/review/ReviewTimeline.vue`）

- props：`days: ReviewTimelineDay[]`；emits：`open: [notePath: string]`；
- 横向 7 等分网格（窄屏允许横向滚动）；今天卡高亮边框 + 「今天」角标 + 逾期标注；
- 卡内：日期（MM-DD）/ 星期 / 数量徽章 → 标题列表（默认 4 条，超出显示「+N」，点击展开/收起，展开状态组件内部按天管理）→ 无任务显示「无」；
- 条目 hover 高亮，点击 `emit('open', task.notePath)`。

### 3.3 集成（`views/LearningHubPage.vue`）

复习视图 `learning-hub__intro` 与 `ReviewDueList` 区块之间插入：

```html
<ReviewTimeline :days="reviewTimeline" @open="handleOpenReview" />
```

`reviewTimeline = computed(() => buildReviewTimeline(reviewStore.queue))`——`queue` 变化（评级/入队/删除）后自动重算，无需额外刷新逻辑。

## 五、风险与边界

- **FSRS 冷启动**：历史不足的任务回退 classic 调度，dueAt 语义不变，时间轴不受影响；
- **跨午夜使用**：以 `now` 实时计算，挂载后不轮询；跨天时下次进入视图自然刷新（与 dueTasks 同策略）；
- **大量任务**：时间轴只做展示聚合（O(n) 分组），列表渲染仍由 ReviewDueList 承担，无性能风险。
