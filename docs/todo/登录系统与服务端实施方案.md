### 3. `server/src/db/schema.ts`（新建，全量表）

```ts
users(id TEXT PK, identifier TEXT UNIQUE NOT NULL, plan_id TEXT, plan_expires_at INTEGER,
      quota_tokens INTEGER NOT NULL DEFAULT 0, created_at INTEGER, updated_at INTEGER)
refresh_tokens(id TEXT PK, user_id TEXT NOT NULL, token_hash TEXT UNIQUE NOT NULL,
      device_id TEXT, expires_at INTEGER NOT NULL, revoked_at INTEGER, created_at INTEGER)
api_keys(id TEXT PK, user_id TEXT NOT NULL, key_hash TEXT UNIQUE NOT NULL,
      enabled INTEGER NOT NULL DEFAULT 1, created_at INTEGER, last_used_at INTEGER, revoked_at INTEGER)
verify_codes(id TEXT PK, identifier TEXT NOT NULL, code_hash TEXT NOT NULL,
      expires_at INTEGER NOT NULL, attempts INTEGER NOT NULL DEFAULT 0,
      last_sent_at INTEGER, created_at INTEGER)
plans(id TEXT PK, name TEXT NOT NULL, price_cents INTEGER NOT NULL,
      token_quota INTEGER NOT NULL, model_group TEXT)
orders(id TEXT PK, order_no TEXT UNIQUE, user_id TEXT NOT NULL, plan_id TEXT,
      amount_cents INTEGER NOT NULL, status TEXT NOT NULL DEFAULT 'pending',
      provider TEXT, paid_at INTEGER, created_at INTEGER)
usage_logs(id TEXT PK, user_id TEXT, api_key_id TEXT, model TEXT,
      prompt_tokens INTEGER NOT NULL DEFAULT 0, completion_tokens INTEGER NOT NULL DEFAULT 0,
      cost_cents INTEGER NOT NULL DEFAULT 0, created_at INTEGER)
```

- 时间一律 **epoch 毫秒 INTEGER**；`id` 用 `crypto.randomUUID()` 文本——表结构从书写起兼容 PostgreSQL，未来 Drizzle 切方言即可。
- `verify_codes` 存 `code_hash`（sha256），**不存明文**；`last_sent_at` 支持重发间隔检查。
- 预置种子数据：`plans` 插 3 条（轻量/标准/专业，价格占位，`db:migrate` 时一并插入）。

### 4. `server/src/services/verify-code.ts`（新建，安全核心）

- `generate()`：`crypto.randomInt(0, 1_000_000)` 补齐 6 位数字；`hash(code)` = `sha256(identifier + ':' + code)`（防库泄露撞码）。
- `sendCooldown(identifier)`：60s 重发间隔（读 `last_sent_at`）；`dailyLimit`：按 identifier 当日计数 ≤ 5。
- `create(identifier)`：删除旧记录 → 插入新记录（hash、expires_at = now + 10min、attempts=0）→ 调 notifier 发送。
- `verify(identifier, inputCode)`：
  1. 取记录；不存在/已过期 → 失败；
  2. `attempts >= 5` → 删除并失败（防爆破）；
  3. `timingSafeEqual(hash(identifier+':'+input), stored)` 比对；
  4. 成功 → **立即删除记录（一次性消费，防重放）**；失败 → attempts+1。

### 5. `server/src/services/notifier.ts`（新建）

- `interface Notifier { send(to: string, code: string, channel: string): Promise<void> }`
- `LogNotifier`：`console.log('[verify-code]', to, code)`（MVP）。
- `createNotifier(env)`：按 `VERIFY_CODE` 环境变量返回实现（`log` 默认），预留 `email`/`sms` 分支（后续填 Resend/阿里云，无需改动调用方）。

### 6. `server/src/services/jwt.ts`（新建）

- `jose` HS256；`signAccessToken(user)`：`{ sub: user.id, plan_id }`，2h；`verifyAccessToken(token)` 校验签名+过期。
- `JWT_SECRET` 从环境变量读取，**启动时校验非空**（缺失即报错退出）。

### 7. `server/src/services/api-key.ts`（新建）

- `generateApiKey()`：`sk-zhizhi-` + `randomBytes(24).toString('base64url')`；`hashKey()` = sha256。
- 明文**仅在登录/签发时返回一次**，库中只存 hash。

### 8. `server/src/services/auth.ts`（新建，业务编排）

- `login(identifier, code, deviceId?)`：
  - `verifyCode` 通过 → `upsertUser(identifier)`（首次登录即注册）；
  - 首次登录（无 api_key）→ `generateApiKey()` 入库并随响应返回；
  - 签发 `access_token`(2h) + `refresh_token`(`randomBytes(32)` base64url，sha256 入库，30d，绑定 device_id)；
  - 返回 `{ access_token, refresh_token, user: { id, identifier, plan_id, quota_tokens }, api_key? }`。
- `refresh(refreshToken)`：sha256 查库 → 校验未吊销/未过期 → **轮换**（旧记录作废，签发新 refresh）→ 返回新 tokens。
- `logout(refreshToken)`：吊销对应记录。

### 9. `server/src/middleware/rate-limit.ts`（新建）

- 内存滑动窗口/令牌桶：`createRateLimiter({ windowMs, max })`，key 取 IP（`@hono/node-server` 的 `getConnInfo`）或 identifier。
- 应用：`send-code` 每 identifier 60s/1 次、每 IP 10min/5 次；`login` 每 IP 10min/10 次。超限返回 `429`。

### 10. `server/src/middleware/auth.ts`（新建）

- `requireAuth`：读 `Authorization: Bearer` → `verifyAccessToken` → `c.set('userId', ...)`；失败 `401`。
- 用于 `/api/me`（后续 orders/usage 复用）。

### 11. `server/src/routes/auth.ts`（新建，`@hono/zod-validator` 校验请求体）

| 端点 | 请求体 | 响应 |
|---|---|---|
| `POST /api/auth/send-code` | `{ identifier: string, channel?: 'email' \| 'sms' }` | 200 `{ success, cooldown_seconds }`；429 限频；400 非法邮箱/手机号 |
| `POST /api/auth/login` | `{ identifier, code, device_id? }` | 200 tokens+user+（首登）api_key；401 验证码错误/过期；429 限频 |
| `POST /api/auth/refresh` | `{ refresh_token }` | 200 新 tokens；401 无效/已吊销 |
| `POST /api/auth/logout` | `{ refresh_token }` | 200 `{ success }` |

### 12. `server/src/routes/me.ts`（新建）

- `GET /api/me`（requireAuth）→ `{ id, identifier, plan_id, plan_expires_at, quota_tokens, api_key_created: boolean, plan: plan|null }`。

### 13. `server/src/app.ts` + `server/src/index.ts`（新建）

- `app.ts`：`new Hono()` → `cors()`（允许所有 Origin，后续收紧）→ 挂载 rate-limit 与路由 → 统一错误处理（返回 `{ error: message }` JSON，`NODE_ENV=production` 时隐藏内部细节）。
- `index.ts`：校验 `JWT_SECRET` 存在 → `serve({ fetch: app.fetch, port: Number(process.env.PORT ?? 8787) })`。
- `.env.example`：`PORT=8787`、`JWT_SECRET=`（必填）、`DB_PATH=./data/zhizhi.db`、`VERIFY_CODE=log`、`NODE_ENV=development`。

### 14. 测试（新建，vitest）

- `verify-code.test.ts`：6 位数字/随机性、hash 不含明文、60s 重发拦截、日上限、一次性消费（成功后重复用被拒）、错 5 次作废、过期失效。
- `jwt.test.ts`：签发/校验通过、过期拒绝、错误 secret 拒绝。
- `rate-limit.test.ts`：窗口内超限返回 429、窗口重置后放行。

## 四、决策与假设

| 项 | 决策 |
|---|---|
| 位置 | 仓库根新建 `server/` 独立 Node 包（ESM），不影响 `study-thread/` 构建 |
| 框架 | Hono + @hono/node-server + @hono/zod-validator |
| ORM | Drizzle + better-sqlite3（同步驱动）；drizzle-kit 仅保留供未来迁移 |
| 鉴权 | jose HS256 access_token(2h) + 不透明 refresh_token(30d, 轮换, 库存 sha256) |
| 验证码 | 6 位数字，10 分钟 TTL，hash 存储，一次性消费，错 5 次作废，60s 重发，日 5 条，IP 限频 |
| 验证码通道 | MVP 日志输出（LogNotifier）；Email/Sms Notifier 接口预留 |
| 官方 Key | `sk-zhizhi-*`，明文仅首登返回一次，库存 sha256 |
| 数据库 | SQLite 单文件（默认 `server/data/zhizhi.db`），表结构按 PG 兼容书写 |
| 节点版本 | 假设 Node ≥ 20（better-sqlite3 v11 要求） |
