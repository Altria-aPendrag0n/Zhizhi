### 1.3 缺口结论

商业闭环断点：**注册后无额度可用 → 无任何开通套餐的途径 → 无法收款**。
上线硬缺口：验证码只打日志、无找回密码、无部署运维与合规文本。
方案主线：**兑换码（卡密）先跑通收款闭环**（个人开发者无需支付资质），在线支付（支付宝当面付/微信 Native）作为 P1 预留接口位。

## 二、正式上线目标与验收标准

1. **账号**：新用户在真实环境完成「邮箱收码 → 注册 → 登录 → 忘记密码重置 → 注销」全流程；验证码真实到达邮箱（到达率 ≥ 95%）。
2. **商业闭环**：管理台生成兑换码 → 用户在客户端输入兑换码 → 套餐即刻生效（额度到账 + 模型分组生效）→ 对话实时扣费 → 客户端可见用量与余额；套餐到期后自动降级 default 组且额度保留。
3. **安全**：生产环境强制 JWT\_SECRET / CHANNEL\_ENC\_KEY / CORS 白名单 / HTTPS；登录按账号防爆破；全链路无明文密钥落盘。
4. **可运维**：一键部署脚本 + systemd 守护 + SQLite 自动备份（可恢复演练）+ /healthz 健康检查 + 管理台总览可观测。
5. **合规**：客户端注册处勾选用户协议与隐私政策；服务端支持账号注销（数据匿名化）；国内服务器需完成 ICP 备案（周期性外部依赖，尽早启动）。

## 三、总体架构（增量部分）

```
客户端（Tauri）
  OfficialModelPage：套餐中心（当前套餐/余额/兑换码/用量图表/协议） + 忘记密码流
        │  /api/plans  /api/plans/redeem  /api/usage/summary  /api/auth/forgot-password …
        ▼
服务端（Hono）
  routes/plans.ts（新增）        套餐列表 / 兑换 / 我的订单
  routes/auth.ts（扩展）         forgot-password / reset-password（复用 verify_codes，加 purpose 列）
  services/notifier.ts（扩展）   SmtpNotifier（nodemailer），VERIFY_CODE=email + SMTP_* 配置
  services/redeem.ts（新增）     兑换码核销事务（码校验 → orders 落单 → plan 生效 + 额度充值）
  services/quota.ts（新增）      套餐生效统一入口（plan_id/plan_expires_at 续期 + quota_tokens 累加）
  db/schema.ts（扩展）           redeem_codes / password_resets(或 verify_codes.purpose) / plans 种子
        │
  网关（零改动）：已有 model_group 控制、额度预检与原子扣减、到期回退 default
```

设计原则：**额度（quota\_tokens）与套餐（plan）解耦**——quota 是"油箱"（累计充值，用完为止），套餐是"加油券 + 车型"（决定 model\_group 与有效期）。网关对到期/降级的语义已实现，无需改动。

## 六、风险与决策点

1. **支付资质**（关键路径决策）：兑换码方案规避资质问题，但卡密售卖渠道（发卡平台）自带手续费与信任成本；若已有个体户/企业资质，可将 S4 的 routes/plans.ts 预留支付下单接口与 S4 并行设计，避免返工。
2. **邮件到达率**：推荐阿里云邮件推送（国内到达率好、有 SMTP 接口）或腾讯 SES；发信域名必须配置 SPF/DKIM，否则进垃圾箱——S1 验收标准含真实邮箱到达测试。
3. **ICP 备案周期**（1–4 周）：决定服务器选境内外。境外服务器可先上线但国内访问质量与合规风险自担；建议方案确认后立即启动备案，与 S1–S8 开发并行。
4. **SQLite 并发上限**：当前单文件库在低并发（数百用户）下足够；用量激增时迁移 PostgreSQL（schema 已按兼容设计），非本次范围但需在管理台总览关注 WAL 锁等待。
5. **额度语义**已定案：quota 累计充值不随套餐过期清零；套餐仅决定模型分组与有效期。若运营上需要"月度重置"，在 S4 的 applyPlanToUser 中改语义即可（集中单点）。

## 七、执行顺序与依赖

```
S1(邮件) ──┬─→ S2(忘记密码) ─→ S7(客户端账号安全) ─┐
           └─→ S3(体验额度) ─┐                     │
S4(套餐/兑换码) ─→ S5(管理台) ─┴─→ S6(客户端套餐中心) ─┼─→ S11(验收)
S8(注销) ─────────────────────────→ S7 ──────────────┤
S9(部署) ── S10(合规/备案，并行) ─────────────────────┘
```

S1 与 S4 无依赖可并行起步；S6/S7 汇合后进入 S11；S9/S10 越早启动越好（备案周期长）。
