# 客户端登录接入实施方案（Phase 1 收尾：客户端）

> 依据：《客户端登录与服务端安全同步设计调研》（`docs/research/客户端登录与服务端安全同步设计调研.md`）、《登录系统与服务端实施方案.md》（服务端已交付，见 [21-auth-server](../code-wiki/21-auth-server.md)）。
> 本次范围（已确认）：**仅客户端 + 服务端配套**——Rust 接入 `tauri-plugin-keyring`（OS 钥匙串）、`stores/auth.ts`（登录状态机）、`api/zhizhi-api.ts`（Bearer + 401 自动刷新）、OfficialModelPage 真实登录流、官方 Provider 接线、Tauri CSP 更新、服务端 CORS 生产收紧、配套测试。服务端 Phase 2（支付 / LLM 网关 / usage 接口）不在本次。
> 技术栈（沿用）：Vue 3 + Pinia + TypeScript + Vitest；Tauri v2（Rust）；服务端 Hono（只改 CORS 一处）。

## 一、当前状态分析

- 服务端 Phase 1 已交付：`POST /api/auth/send-code|login|refresh|logout`、`GET /api/me`，30 例测试全绿；`server/src/app.ts` 的 `cors()` 目前**允许所有 Origin**（生产需收紧）。
- 客户端现状：
  - [OfficialModelPage.vue](../study-thread/src/views/OfficialModelPage.vue) 为 UI 骨架（登录表单 + 套餐卡片），交互统一 `handleNotReady` 提示"未上线"。
  - [settings.ts](../study-thread/src/stores/settings.ts) 把 apiKey/baseUrl **明文存 localStorage**（`study-thread-settings`）；官方 Key 绝不能走这条路。
  - [provider-factory.ts](../study-thread/src/api/provider-factory.ts) 的 `openai-compat` 适配器可直接对接官方网关（`createProvider({ type, apiKey, baseUrl, model })`，类型见 [types/index.ts](../study-thread/src/types/index.ts) 的 `ProviderConfig`）。
  - Rust 侧已装插件：opener / dialog / updater / process；**无 keyring 类凭据插件**。
  - [tauri.conf.json](../study-thread/src-tauri/tauri.conf.json) 的 CSP `connect-src` 写死各家 LLM 域名，**缺官方 API 地址**。

## 二、总体设计

```
┌──────────────────────────────────────────────────────────────┐
│ 渲染进程（Vue）                                                │
│  OfficialModelPage（登录表单/已登录态）                          │
│      │                                                       │
│  stores/auth.ts（状态机：anonymous→authenticating→authenticated）│
│      │  access_token 仅内存；api_key 仅内存（构造 Provider 时用）  │
│  api/zhizhi-api.ts（fetch：Bearer 注入 + 401 single-flight 刷新）│
│      │                                                       │
│  utils/secure-store.ts（钥匙串封装：refresh_token / api_key）    │
│      │                                                       │
│  stores/settings.ts（officialApiBaseUrl，非敏感，localStorage） │
└──────┬───────────────────────────────────────────────────────┘
       │ Tauri IPC（invoke / 插件 JS API）
┌──────▼───────────────────────────────────────────────────────┐
│ Rust 后端                                                      │
│  tauri-plugin-keyring → OS 钥匙串（Windows Credential Manager / │
│  macOS Keychain / Linux Secret Service）                       │
└──────────────────────────────────────────────────────────────┘
       │ HTTPS（生产）/ http://127.0.0.1（开发）
┌──────▼───────────────────────────────────────────────────────┐
│ server/（Hono）                                                │
│  /api/auth/*（send-code/login/refresh/logout）+ /api/me        │
│  CORS：生产按 Origin 白名单（tauri://localhost 等）              │
└──────────────────────────────────────────────────────────────┘
```

核心安全边界（调研结论）：**refresh_token 与官方 api_key 只进 OS 钥匙串，绝不进 localStorage**；access_token 只留内存；refresh 轮换由服务端保证，客户端 single-flight 消费。

### 2. 前端：钥匙串封装 `src/utils/secure-store.ts`（新建）

集中管理凭据条目名与初始化，便于测试 mock：

```ts
import { initializeKeyring, setPassword, getPassword, deletePassword, hasPassword } from 'tauri-plugin-keyring'

const SERVICE = 'com.study-thread.app'
export const REFRESH_TOKEN_KEY = 'zhizhi.refresh_token'
export const API_KEY_KEY = 'zhizhi.api_key'

export async function initSecureStore(): Promise<void> { await initializeKeyring(SERVICE) }
export async function setRefreshToken(t: string): Promise<void> { await setPassword(REFRESH_TOKEN_KEY, t) }
export async function getRefreshToken(): Promise<string | null> { return (await hasPassword(REFRESH_TOKEN_KEY)) ? await getPassword(REFRESH_TOKEN_KEY) : null }
export async function deleteRefreshToken(): Promise<void> { await deletePassword(REFRESH_TOKEN_KEY) }
// api_key 同理：setApiKey / getApiKey / deleteApiKey / hasApiKey
export async function clearCredentials(): Promise<void> { await deleteRefreshToken(); await deleteApiKey() }
```

### 4. API 客户端 `src/api/zhizhi-api.ts`（新建）

```ts
export class ZhizhiApiError extends Error {
  constructor(message: string, readonly status?: number, readonly retryAfterSeconds?: number) {}
}

export async function sendCode(identifier: string): Promise<{ cooldown_seconds: number }>
export async function login(identifier: string, code: string, deviceId?: string):
  Promise<{ access_token: string; refresh_token: string; user: OfficialUser; api_key?: string }>
export async function refreshToken(refreshToken: string):
  Promise<{ access_token: string; refresh_token: string }>
export async function logout(refreshToken: string): Promise<void>
export async function fetchMe(accessToken: string): Promise<OfficialUser>
```

- 内部 `request(path, { method, body, auth })`：baseUrl 取 `settings.officialApiBaseUrl`；`Authorization: Bearer`；JSON 序列化。
- **401 single-flight**：模块级 `let refreshing: Promise<string | null> | null`；接口 401 → 取钥匙串 refresh_token → `refreshToken()`（并发请求共享同一次刷新）→ 成功后写回钥匙串 + 更新内存 token → 重放原请求一次；刷新失败或 refresh 自身 401 → 清凭据并抛 `ZhizhiApiError('SESSION_EXPIRED')`（auth store 捕获后回登录态）。
- 错误归一：`429` 带 `retry_after`；网络失败抛可识别的 `ZhizhiApiError('NETWORK')`；其余 4xx/5xx 透传 message。
- baseUrl 校验：非 `https://` 且非 `http://127.0.0.1`/`http://localhost` 时拒绝注入令牌（防误配/钓鱼，调研 §五）。

### 5. 登录状态机 `src/stores/auth.ts`（新建，Pinia）

```
state:  status: 'anonymous' | 'authenticating' | 'authenticated'
        user: OfficialUser | null
        accessToken: string        // 仅内存
        apiKey: string             // 仅内存（钥匙串读入）
actions:
  sendCode(identifier)             → zhizhiApi.sendCode（UI 倒计时用 cooldown_seconds）
  login(identifier, code)          → zhizhiApi.login
                                    → setRefreshToken / setApiKey（首登有 api_key 时）
                                    → 内存存 accessToken、apiKey、user
                                    → settings.officialApiEnabled = true
                                    → fetchMe() 刷新额度
  restore()                        → initSecureStore → getRefreshToken()
                                    → 无 → anonymous
                                    → 有 → silentRefresh()
  silentRefresh()                  → 用钥匙串 refresh_token 换新 tokens
                                    → 写回钥匙串、更新内存、拉 fetchMe
                                    → 失败 → clearCredentials + anonymous（"登录已过期"）
  fetchMe()                        → 更新 user（plan/quota 同步）
  logout()                         → zhizhiApi.logout（尽力而为，失败不阻塞）
                                    → clearCredentials + 清内存 + settings.officialApiEnabled=false
```

- 应用入口（`App.vue` onMounted 或 main.ts）：`await authStore.restore()`——启动静默续期，失败不弹窗（保持匿名即可）。
- 提供 `isOfficialActive` getter（= status==='authenticated'），供 provider 接线判断。

### 6. OfficialModelPage.vue：接真实登录流

- 保留现有布局（登录引导 / 套餐预览 / 如何工作三块）。
- 登录区：
  - anonymous：账号输入 + 验证码输入 + 「获取验证码」（60s 倒计时，按钮禁用）+ 「登录」（loading/禁用）；错误 toast（401 验证码错误 / 429 限频含秒数 / 网络）。
  - authenticating：按钮 loading。
  - authenticated：显示账号（identifier）+ 套餐/剩余额度（`/api/me`）+ 用量说明 + 「登出」按钮（确认后 logout，回 anonymous）。

## 四、决策与假设

| 项 | 决策 |
|---|---|
| 凭据存储 | OS 钥匙串（tauri-plugin-keyring）；refresh_token / api_key 不进 localStorage；access_token 仅内存 |
| 续期方式 | 401 触发 single-flight 刷新；启动时 restore 静默续期 |
| 登录鉴权 | 复用服务端验证码登录（无 OAuth，账号即邮箱/手机号） |
| 官方地址 | 默认构建环境注入（dev 127.0.0.1:8787 / prod api.zhizhi.app），设置页可改；CSP 放行 `https:` + `http://127.0.0.1:8787` |
| Provider | 官方 = `openai-compat` + 官方 baseUrl + 内存 api_key；LLM 链路零改动 |
| CORS | 生产按 Origin 白名单（tauri://localhost 等），`CORS_ORIGIN` 可覆盖；开发保持全放行 |
| 服务端改动面 | 仅 `app.ts` CORS 一处 + `.env.example`（不动既有 30 例测试） |
| 模型占位 | `officialModel` 默认 `glm-4.7-flash`（免费引流），Phase 2 网关定档后调整 |
| 测试范围 | 前端 3 个新测试文件 + 既有全量回归（1057+）；服务端回归 30 例 |
